# 文献综述

把输入文件夹里的论文当成一个任务。读 PDF 放在子任务里。父代理维护清单、派子任务、把证据写成笔记库里的笔记，并写综合综述。

不要只处理一篇就要求用户说“继续”。至少两篇论文可读取时，默认整理方法差别，不需要用户额外要求写对比。

只依据实际读取的 PDF 文字和 Vault 中已有笔记。不要凭记忆补充作者、数字、实验结果或未读到的方法。区分论文明确陈述的内容与基于已读材料作出的综合判断。

对话记不住上次停在哪。进度以工作区里的 `plan.md` 和 `progress.md` 为准。

## 两条路径

笔记库里的成品用 `create_note`、`insert_text`、`delete_lines`。这些写入会停下来等用户确认。确认后继续本次任务。预览后文件变了、写入被拒绝时，不要重试同一次修改，告诉用户文件已变。

工作区里的过程文件用 `write_file`。它立刻写入，已有文件会被替换，不要等确认。不要写 `skills/` 和 `sessions/`。

1. 笔记库输出文件夹用用户指定的路径。未指定时用 `survey/`。成品是：
   - `<输出文件夹>/overview.md`：综合综述。
   - `<输出文件夹>/papers/<论文短名>.md`：单篇论文笔记。
   - `<输出文件夹>/methods/<方法短名>.md`：按需建立的方法细节笔记。
2. 工作区目录是 `jobs/<短名>/`。短名由输出文件夹得到，把斜杠换成连字符，例如 `survey`、`Planning/survey` 得到 `planning-survey`。
3. 父代理用 `write_file` 维护 `jobs/<短名>/plan.md`。每篇一行，记下 PDF 路径、论文短名、scope、状态（待读、已读、受限）、证据路径、笔记库路径。
4. 每篇论文的 scope 是 `jobs/<短名>/<论文短名>`。论文短名不要含斜杠。子任务只把证据写到 `<scope>/evidence.md`，整篇写一次，不要反复重写同一文件。
5. `jobs/<短名>/progress.md` 由 `run_subtask` 返回后程序写入，一节对应一个 scope。父代理只用 `read_file` 看它，不要用 `write_file` 改它。
6. 文件名简短、稳定，能够区分论文或方法。不要为同一材料重复建立多个版本。
7. 笔记库路径已存在时，先 `read_note`。可复用的内容直接复用，需要更新的用 `insert_text` 或 `delete_lines`。不要用 `create_note` 覆盖已有文件，也不要因为一个路径已存在就终止整个任务。

## 开始时

1. 输入文件夹用用户指定的路径。未指定时用 `papers/`。用 glob 查找其中全部 PDF，包含子文件夹。合并结果、去重并按路径排序。
2. 若 `plan.md` 或 `progress.md` 已在，先 `read_file`。没有 `plan.md` 就按清单新建。没有 `progress.md` 就从零开始。
3. 对照笔记库里已有的论文笔记。只有能够确认对应同一 PDF，且内容足以支持本次综述时才可复用，并在 `plan.md` 里标为已读。缺失的重要内容仍要派子任务补读。来源对应不清楚时，不要仅凭相似文件名跳过论文。

## 阅读：每篇一次子任务

一次回复里只调用一个 `run_subtask`。等它返回后，再派下一篇。

子任务看不到本技能，用户消息只有 `task`。`task` 只由下面这七行组成。前两行的路径从 `plan.md` 抄来，必须是这一篇自己的路径。不要把本技能的其他段落写进 `task`，不要写尖括号或占位词。

1. `只读这一个 PDF：` 后面接 `plan.md` 里这一篇的 PDF 路径，原样照抄。
2. `证据只写这一个文件：` 后面接这次参数 `scope`，再接 `/evidence.md`。
3. 先调用 `tool_describe`，name 为 `read_pdf`。下一步才能 `read_pdf`。
4. 用 `read_pdf` 读取第 1 行的那个 PDF，从第 1 页开始，每次传 limit 4。用返回的 offset 继续，直到覆盖摘要、问题背景、核心方法、主要实验和结论。方法或结论依赖后续章节、讨论或附录时，继续补读。不必读取与综述无关的附录。不要读其他 PDF。不要只读摘要就描述详细方法。
5. 记录关键内容的来源页码。某页无法提取文字时，记录页码及影响。图表无法从提取结果中可靠理解时，不猜测其内容。
6. 只为第 1 行那个 PDF 的正文里出现、且需要链接到已有笔记的概念调用 `search_notes`。阅读候选笔记的标题和相关正文，确认它确实解释该概念。记下 Vault 内的真实相对路径，省略 `.md`。候选有多个时，用带目录的路径。无法判断或没有合适笔记时写「无」。没有这样的概念就写「无」。不要为此新建背景笔记。
7. 用 `write_file` 把证据写到第 2 行的那个文件，只写这一次。不要写其他路径。证据是简短草稿，不要把 PDF 逐页抄进去。式子写成 Markdown 数学：行内用 `$...$`，独占一行用 `$$...$$`。只转写读到的式子；抽取出的符号对不上时保留原文，不要编造没有读到的式子。

证据按「单篇论文笔记」的结构来写，并加上：

- 第一行是 `# 论文标题`。
- PDF 相对路径、主要读取范围、无法提取的页码。
- 概念一行一个：名称，以及确认过的路径或「无」。
- 若某个方法展开后会打断主线，另给方法短名和一段草稿。简单方法留在论文笔记里。
- 与其他论文的关系先不写。双方相关内容都已读过之后，由父代理补。

父代理不要自己 `read_pdf`。返回后以文件为准：

- `status` 为 `ready`，且 files 里有 `evidence.md`：`plan.md` 标为已读。内容用 `read_file` 读证据，不要依赖返回文字。返回里的回答只保留前 800 字。证据里没有概念行（名称，以及确认过的路径或「无」）时，不要标成已读。用同一个 scope 再派一次，task 只要求补上这一行。
- `status` 为 `partial` 或 `failed`：标为受限，记下返回里的说明。不要当成已读。可以用同一个 scope 再派一次。
- 一篇接一篇派。不要每篇停下来问用户。若这次运行在笔记还没写完时停下，`plan.md` 写明停在哪一篇。下次从 `plan.md` 和 `progress.md` 继续。尚未处理完所有论文时，不要把结果称为完整综述。

## 链接到已有背景知识

写笔记库笔记时，使用证据里已经确认的路径。概念在每篇笔记第一次出现时添加链接，后续出现不重复添加。链接写成 `[[目录/笔记名|显示名]]`，目录和笔记名用证据里记下的真实路径。别名只用于显示。没有路径时保留概念名称。新建的论文笔记和方法笔记同样使用真实相对路径互相引用。

## 单篇论文笔记

证据就绪后，由父代理写入笔记库 `<输出文件夹>/papers/<论文短名>.md`。笔记保持简短，作为综合综述的证据入口。

第一行必须是 `# 论文标题`。随后写 PDF 相对路径和主要读取范围。包含以下内容：

### 问题背景

说明论文要解决什么，以及已有做法具体卡在哪里。

### 核心方法

解释方法的主要思路和关键步骤。保留必要的方法名、公式和数字，不逐段翻译论文。公式用 Markdown 数学写出，行内 `$...$`，独占一行 `$$...$$`。证据里若仍是线性公式，写入笔记时转写。抽取出的符号对不上时保留原文，不要补没有读到的式子。

较长的方法细节链接到单独的方法笔记。与其他论文的关系只有在双方相关内容都已读过时才写。

### 主要结果与限制

写支撑方法的主要结果及其实验条件，再写作者承认的限制和读取缺口。

缺失且影响理解的信息明确标记为“未读取到”或“原文未明确说明”。

## 方法细节笔记

只为综述中确实重要、且展开后会打断主线的方法建立单独笔记。简单方法直接在论文笔记中解释。路径是 `<输出文件夹>/methods/<方法短名>.md`。

方法笔记包含：

- 方法要解决的问题。
- 核心步骤、必要公式或伪代码。公式同样写成 Markdown 数学，不要留成一行纯文本。
- 关键假设和适用条件。
- 与其他已读方法的具体差别。
- 来源论文链接及相关页码。

来源论文的解释与已有背景笔记中的通用知识分开表述。不要为每个术语都建立一篇笔记。

## 综合综述

在所有可处理论文都已读完或复用后，写 `<输出文件夹>/overview.md`。依据各篇 `evidence.md` 和已写入的笔记，不要再读 PDF。

标题使用研究主题。开头简要说明覆盖哪些论文及材料范围，然后组织为以下部分。

### 问题背景

用连贯段落解释这些论文涉及什么共同问题、为什么值得解决、已有方法有哪些关键瓶颈。若论文关注不同子问题，先明确分类。背景概念首次出现时链接到 Vault 中已有笔记。

### 解决思路

按方法思路或所解决的瓶颈组织内容，说明每一类方法的核心做法。主文保留理解研究主线所需的信息，详细步骤链接到论文笔记或方法笔记。避免把综述写成逐篇摘要的简单拼接。

### 不同方法的差别

使用简洁的比较表和必要段落，比较实际读到的差异，例如优化目标或所需监督、信息来源与输入条件、训练或搜索或推理流程、额外计算与数据需求、适用场景和关键限制。

差别应落到具体步骤、假设或资源需求，不写空泛的“各有优劣”。数据集、模型规模、任务或计算预算不同的实验，不直接按数字排出优劣。比较结论必须能追溯到来源论文。

### 总结与待解决问题

简要总结方法之间的关系和仍未解决的问题。区分作者明确提出的问题与基于本次材料作出的综合判断。读取不完整时说明哪些结论受影响。

## 写入与链接检查

先写论文笔记和方法笔记，再写引用它们的综合综述。目标尚未写入时，不把链接检查当成最终结果。

完成笔记库写入后：

1. 对每篇新建或修改的笔记调用 `note_links`，direction 使用 `outgoing`，检查链接解析到的真实路径及 ambiguous 状态。
2. 对同一批笔记调用 `note_links`，direction 使用 `unresolved`，检查未创建目标。
3. 每次都传具体 path，不省略 path 扫描整个 Vault。
4. 检查链接是否指向预期笔记。能够解析不代表引用正确。
5. 正文里出现过、证据里也有路径的概念，若 outgoing 没有对应链接，先用 `insert_text` 或 `delete_lines` 补上，再声称检查完成。拼写或路径错误同样修正，确认后再检查一次。
6. 无法解决的歧义或未创建目标，在最终回答中明确列出。

## 完成后回答

简要报告：

- 综合综述的相对路径。
- 新建或更新的论文笔记和方法笔记。
- 已处理、复用及读取受限的论文数量。
- 尚未处理的论文或重要信息缺口。
- 未解决的链接问题。

只有在全部目标论文已处理，或无法处理的部分已明确说明后，才报告本次任务完成。
